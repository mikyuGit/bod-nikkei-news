# BoD 日経ニュース収集

GoogleニュースRSSに掲載された日経の日本語見出しを取得し、既存のCloudflare Workerへ渡します。Workerが金利・国債・為替・中央銀行・経済指標などを分類し、Discordのマーケットニュースチャンネルへ配信します。記事本文やAI要約は取得しません。

## 自動実行

- `.github/workflows/nikkei-collect.yml`：5分間隔のスケジュール（UTCの3、8、13、18…分）。
- 初回は掲載済み記事を記録し、過去記事を一括投稿しません。
- 以降の新着・見出しの更新はWorkerのD1で重複を判定し、既存の2分間隔の配信処理へ送ります。
- Googleの掲載遅延、GitHubの実行待ち、Discordの送信待ちがあります。5分ごとの実行や数分以内の配信は保証されません。
- 公開リポジトリの標準GitHubホストランナーを使用します。有料ランナー、AI API、有料ニュースAPIは使用しません。

## 認証

このリポジトリのmainブランチ上にある指定Workflowだけが、GitHubの短時間のOIDCトークンでRSSを送信できます。Workerは署名、対象URL、リポジトリID、所有者ID、ブランチ、Workflow、期限を検証します。Discord Botトークン・Cloudflare APIトークンをこのリポジトリやGitHub Secretsへ保存する必要はありません。

## 確認

GitHubの **Actions → Nikkei Japanese market news** で緑の成功マークとログを確認します。`google_http_status: 200` と `worker.ok: true` が取得・受け渡し成功です。`matched` は金融関連の件数、`queued` はその回に送信待ちへ登録した件数です。同じ記事しかなければ`queued: 0`が正常です。

手動取得は **Run workflow** から実行します。`Post one clearly labelled test card to Discord` を選ぶと、対象の最新記事を1件だけ【テスト】付きで投稿します。通常は選ばないでください。同じ記事のテストを再実行すると元のテスト投稿を更新します。

Workerの管理画面のニュース稼働状況では、`nikkei_collector: github`、`last_success_jst`、`last_error`、`info.received_at_jst` を確認できます。日経のプレビューはGitHubから最後に受け取ったRSSを利用します。

## 停止と復旧

- 日経だけを停止：Cloudflare Workerの変数 `NEWS_NIKKEI_ENABLED` を `false` にして反映。
- 全市場ニュースを停止：`NEWS_ENABLED=false`。
- 収集自体を停止：ActionsのこのWorkflowを **Disable workflow**。
- 再開：スイッチを戻しWorkflowを有効化。投稿済み履歴は削除しないでください。
- 公開リポジトリの定期実行は、リポジトリで60日間活動がないと無効になることがあります。自動実行が止まった場合はActionsで再有効化してください。
- Google RSSの取得エラー時はその回の処理を失敗として記録し、記事0件として基準を更新しません。
- Google RSSのHTTP 429・500・502・503・504や一時的な通信失敗は、初回を含め最大3回取得します。失敗後は10秒、さらに失敗したら20秒待ちます。通常成功時の待機はなく、取得回数の上限・5分間隔の定期実行・Workerへの受け渡し回数は増やしません。認証・媒体の検証エラーは再試行で無視しません。
- Workerの未受信通知は3時間を超えた場合に1回だけ送ります。1時間の未受信ではDiscordへ通知しません。受信再開後に監視状態を解除します。
- 2026年10月19日にCronを再登録しました。設定は5分間隔ですが、GitHubの起動遅延や欠落を解消する保証はありません。

## リンク

通知のリンクはGoogleニュースRSSにある記事リンクを使います。Googleニュースを経由して日経の記事へ移動します。Workerは有料記事の本文や認証を取得しません。

## 政府保証付き証書借入の入札カレンダー

`Government-guaranteed loan calendar` が毎時23分（UTC、日本時間も毎時23分）に公式公表を確認します。GitHubの起動遅延があるため、毎時の実行時刻は保証されません。

- 対象：原子力損害賠償・廃炉等支援機構（NDF）、産業革新投資機構（JIC）、JOGMEC、民間資金等活用事業推進機構、電力広域的運営推進機関、民間都市開発推進機構。
- 公開された政府保証付きの借入予定だけを、Workerの「本日の入札」「次の10件」へ国債・特別会計借入と日付順で統合します。政府保証債・一般の調達入札・政府保証なしの借入・非公開の案件は対象外です。入札結果の通知は追加しません。
- 公式HTMLと、そのページに実在する公告PDFを確認します。公告日や参加申込期限を入札日として使いません。確定できない日付は掲載しません。JIC・NDFの年間予定も確認し、詳細公告があれば統合します。
- 予定額・借入日・償還期限は公式資料にある範囲で表示します。財務省の承認が政府保証の条件の場合は注記します。
- PDFの読み取りは公開リポジトリの標準ランナーで実施し、Workerには最大64KiBのメタデータのみを送信します。新たなCloudflare Cronや有料サービス・永続トークンは追加しません。
- 1回の取得は最大36URL、各資料は2MiB、PDFは最初の5ページ・解析15秒まで。HTTP 429/一時的な5xx等は10秒後に1回再試行します。ジョブ全体は12分で打ち切ります。
- 取得失敗では前回の予定を保持し、カレンダーに再確認の注記を表示します。正常に確認した一覧から消えた予定は削除します。48時間以上確認できていない場合も注記します。GitHub Actionsの失敗メールとWorker管理画面の「政府保証借入の取得状況」で確認できます。
- 認証は同じリポジトリのmain・専用Workflow・専用audienceに限定したGitHub OIDCです。日経Workflowの認証をこの経路へ流用することはできません。

手動取得はActionsで `Government-guaranteed loan calendar` → `Run workflow` を実行します。収集だけではDiscordに新規カードを投稿せず、朝の案内とその後の既存の更新処理で反映します。過去の入札予定は新規投稿しません。
